# Epic 4 — Production-профиль и UX Telegram-бота

**Требования PRD:** `IDENTITY-01`, `IDENTITY-02`, `UX-01`

**Зависимости:** [Epic 1](./01-giveaway-creation.md), [Epic 2](./02-participants-and-referrals.md), [Epic 3](./03-draw-and-reroll.md)

## 1. Цель

Превратить функциональный MVP из технического smoke-бота в узнаваемый официальный Telegram-бот розыгрышей Татьяны Стрельчук, не меняя бизнес-правила создания, участия, выбора победителей и перевыбора.

## 2. Пользовательский результат

- В профиле Telegram видны согласованные имя, аватар и понятные описания вместо тестовых значений.
- Участник сразу понимает, что открыл официальный бот розыгрышей и зачем нужен `/start`.
- Член команды видит только команды управления и последовательную русскоязычную лексику.
- Настройку профиля можно безопасно повторить после создания нового production-бота или изменения метаданных.
- Smoke-бот нельзя случайно переоформить production-командой.

## 3. Production-идентичность

| Поле | Значение |
|---|---|
| Username | `@strelchuk_giveaways_bot` |
| Отображаемое имя | `Розыгрыши Татьяны Стрельчук` |
| Краткое описание | `Официальный бот розыгрышей Татьяны Стрельчук` |
| Полное описание | `Официальный бот розыгрышей Татьяны Стрельчук. Помогает проверить условия участия, зарегистрироваться и узнать результат. Управление розыгрышами доступно только команде.` |
| Аватар | выбранная концепция: коралловая подарочная лента и вспышка на тёплом светлом фоне |

Полное описание не обещает автоматического определения ботов, приватных каналов или других функций вне PRD.

Username создаётся или подтверждается через BotFather. Остальные поля применяются отдельной идемпотентной операцией через актуальный Telegram Bot API.

## 4. Настройка профиля

Перед первым изменяющим вызовом операция:

1. загружает локальную production-конфигурацию без вывода token;
2. проверяет наличие и формат целевого JPG-аватара;
3. вызывает `getMe`;
4. требует точного username `strelchuk_giveaways_bot`;
5. прекращает работу без изменений при любом несовпадении.

После preflight операция применяет имя, полное описание, краткое описание, команды и статический JPG-аватар. Telegram не предоставляет транзакцию для этих вызовов, поэтому rollback не моделируется. Каждый шаг идемпотентен, результат каждого шага выводится без секретов, а повторный запуск приводит частично настроенный профиль к целевому состоянию.

Исходный выбранный PNG хранится как master-asset. Для Telegram хранится детерминированно подготовленный JPG без изменения композиции. Оба файла остаются квадратными и проходят проверку читаемости внутри круглого crop на малом размере.

## 5. Команды и текстовый UX

Default scope для обычного пользователя содержит только:

- `/start` — `Открыть бот розыгрышей`.

Для каждого Telegram ID из production allowlist задаётся более конкретный private-chat scope:

- `/start` — `Открыть панель управления`;
- `/new` — `Создать розыгрыш`;
- `/giveaways` — `Мои розыгрыши`;
- `/cancel` — `Отменить розыгрыш или настройку`.

`/start` без deep-link payload разделяется по роли:

- обычный пользователь получает: `Это официальный бот розыгрышей Татьяны Стрельчук. Чтобы участвовать, откройте кнопку «Участвовать» в конкурсном посте.`;
- оператор получает: `Добро пожаловать в «Розыгрыши Татьяны Стрельчук».\n\n/new — создать розыгрыш\n/giveaways — открыть мои розыгрыши\n/cancel — отменить розыгрыш или текущую настройку`.

Deep-link payload `join_`, `ref_` и `ci_` по-прежнему обрабатывается до обычного `/start`. Неавторизованные `/new`, `/giveaways`, `/cancel` и административные callbacks сохраняют fail-closed ответ.

Сообщения, которые затрагивает эпик, следуют одному тону: коротко, по-русски, без внутренних state/error names, без восклицательной рекламной стилистики и без обещаний, которых нет в PRD.

Эпик не перестраивает мастер, callback-модель или доменные состояния. Редактура существующих сообщений ограничена тестовой лексикой, названиями действий и явно техническими формулировками на пользовательской поверхности.

## 6. Ошибки и безопасность

- Неизвестный или smoke username блокирует все profile writes.
- Недоступный avatar, не-JPG файл или ошибка локальной валидации блокируют все profile writes.
- Ошибка одного Telegram write завершает команду с ненулевым кодом и названием шага; token и сырой request не логируются.
- Повторный запуск после частичного успеха безопасен и не создаёт дубликаты команд или фото.
- `BOT_TOKEN`, allowlist и production-конфигурация не добавляются в Git.
- Profile-команда не запускается автоматически при каждом старте основного long-polling процесса.

## 7. Критерии приёмки

- `getMe` production-бота возвращает username `strelchuk_giveaways_bot`.
- В Telegram видны согласованные имя, короткое и полное описания и выбранный аватар.
- Аватар сохраняет главный силуэт в круглом crop и различим в списке чатов.
- Обычный пользователь видит только `/start`; allowlisted оператор видит четыре административные команды.
- Обычный `/start` объясняет участие через кнопку конкурсного поста и не отвечает техническим отказом.
- `/start` оператора больше не содержит `Gift Bot готов` или тестовое имя.
- Запуск profile-команды с token smoke-бота завершается до первого изменяющего вызова.
- Повторное применение к уже настроенному production-боту успешно и оставляет тот же целевой профиль.

## 8. Проверка

- Unit: целевые metadata/command payload, default и operator scopes, точная проверка username, порядок preflight до writes.
- Adapter: обновлённый `/start`, авторизация и неизменность deep-link сценариев `join_`, `ref_`, `ci_`.
- Asset: квадратные размеры, допустимый JPG и circle-safe визуальная проверка.
- Full gate: `pnpm check`.
- Ручной Telegram smoke: отдельный production token, `getMe`, профиль, меню обычного пользователя и меню allowlisted оператора.

Автоматические проверки не доказывают, что реальный профиль Telegram обновлён. Ручной smoke не заменяет unit/full gate.

## 9. Не входит в эпик

- создание нового username без участия BotFather;
- редизайн доменного мастера или изменение бизнес-правил;
- web-интерфейс, Mini App и пользовательский кабинет;
- автоматическое распознавание ботов, CAPTCHA и модерация победителей до публикации;
- запуск процесса, LaunchAgent, резервное копирование и мониторинг Mac;
- переоформление smoke-бота.
