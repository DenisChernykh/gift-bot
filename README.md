# Gift Bot

Telegram-бот для создания, безопасной публикации и отмены розыгрышей. Текущая вертикаль — Epic 1: мастер, собственные и внешние публичные каналы, публикация, отмена и восстановление. Регистрация участников и рефералы намеренно начинаются только в Epic 2.

## Локальный запуск

Нужны Node `24.18.1` (допустимый диапазон `>=24.18.0 <25`) и pnpm `11.15.1` (диапазон `>=11.15.1 <12`). Проверить контракт:

```sh
node --version
pnpm --version
```

Установить зависимости, создать локальную конфигурацию и применить миграции:

```sh
pnpm install
cp .env.example .env
pnpm db:migrate
```

Заполните только локальный `.env`:

```dotenv
BOT_TOKEN=<token from BotFather>
TEAM_TELEGRAM_IDS=<comma-separated numeric Telegram user IDs>
DATABASE_PATH=.data/gift-bot.sqlite
LOG_LEVEL=info
```

`TEAM_TELEGRAM_IDS` — allowlist операторов. Не добавляйте токен, ID команды или SQLite-файлы в Git.

Команды проекта:

```sh
pnpm dev          # TypeScript long polling
pnpm build
pnpm start        # запуск собранного dist/index.js
pnpm check        # lint + tests + build
pnpm db:generate  # сгенерировать новую миграцию после изменения схемы
pnpm db:migrate   # применить существующие миграции
```

`pnpm dev` и `pnpm start` используют long polling, поэтому не запускайте два экземпляра с одним ботом одновременно.

## SQLite и резервная копия

По умолчанию база находится в `.data/gift-bot.sqlite`. Включён WAL: нельзя надёжно копировать только основной файл пока процесс пишет в базу — часть последних данных может находиться в `-wal`. Остановите бота и копируйте согласованную пару базы и её `-wal`/`-shm` файлов, либо используйте штатный SQLite backup. Перед восстановлением сделайте отдельную копию текущей базы.

## Операторский сценарий

В [BotFather](https://t.me/BotFather) создайте тестового или рабочего бота и сохраните выданный token только в `.env`. В каждом публичном канале добавьте бота администратором с правами **публиковать**, **редактировать** и **удалять** сообщения. Канал обязан иметь `@username`.

Свой канал:

1. Оператор из `TEAM_TELEGRAM_IDS` запускает `/new` и проходит шаги: внутреннее название 1–100 символов, 1–50 победителей, будущий дедлайн по Екатеринбургу, рефералы, текст или фото с подписью.
2. На шаге каналов выбирает «Добавить свой канал», открывает `startchannel`-ссылку и добавляет бота администратором с тремя правами.
3. После события Telegram бот показывает найденный канал; оператор нажимает подтверждение, открывает предпросмотр и публикует.

Внешний канал:

1. Оператор на шаге каналов выбирает «Пригласить владельца» и передаёт владельцу одноразовую `/start ci_…`-ссылку (24 часа).
2. Владелец открывает ссылку, добавляет бота через предложенную `startchannel`-ссылку и нажимает подтверждение найденного канала.
3. Это связывает канал только с данным розыгрышем. Владелец не получает доступ к `/new`, `/giveaways` или `/cancel`.

Перед публикацией бот заново проверяет админский статус и все три права. Один и тот же контент публикуется во все подтверждённые каналы; розыгрыш становится `active` только когда сохранён `messageId` каждой доставки. Итоговое опубликованное text-сообщение ограничено 4096 UTF-16 code units, caption фото — 1024; лимит включает название и служебные строки. Переполнение итогового render отклоняется до создания publication run, join-token или delivery.

## Ошибки, восстановление и отмена

- После запуска сначала обрабатываются незавершённые публикации. Если все delivery уже имеют `messageId`, розыгрыш активируется. Частично известные доставки удаляются в обратном порядке; полный откат возвращает `draft`.
- Неизвестный результат отправки, `sending` при падении процесса или неудачный откат переводят в `failed`. Бот не повторяет такую отправку автоматически. Выполните `/giveaways`: карточка `failed` показывает ID розыгрыша, stage, error kind, а для затронутых каналов — `@username`, внутренний channel ID, Telegram chat ID и ссылку на известный пост. Сверьте эти данные с реальными постами и структурированным событием `publication_failed`, затем выберите согласованный ручной путь; не публикуйте поверх неизвестного состояния.
- `/cancel` всегда требует подтверждения. Для активного розыгрыша сначала фиксируется `cancelled` и отзывается активный join-token, затем в базе создаются задачи правки постов. Ошибочные правки повторяются на следующем старте и далее раз в минуту.
- При отмене сообщение заменяется на «Розыгрыш отменён», а кнопка участия убирается. Текст может быть укорочен, чтобы suffix поместился в лимит Telegram.

## Граница участия и безопасность

Публикация Epic 1 создаёт непрозрачную join-ссылку без внутреннего ID. Пока не реализован Epic 2, активная ссылка только сообщает пользователю, что регистрация ещё не доступна: не создаётся запись участника, не проверяется подписка, не начисляются рефералы. Неизвестный, неактивный или отозванный токен недоступен.

Храните `BOT_TOKEN` и ссылки-приглашения как секреты. Токены в базе хешируются; не логируйте и не пересылайте их широким группам. Не делайте внешнего владельца участником allowlist только для подключения канала. Событие `publication_failed` содержит `giveawayId`, `stage`, `errorKind`, `channelId` и `channelUsername`, но никогда token, `BOT_TOKEN` или deep-link payload.
